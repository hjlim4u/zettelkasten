## 📌 라우팅 테이블이 만들어지는 방법에 따른 라우팅의 두 가지 분류는 무엇인가?

라우팅 테이블이 만들어지는 방법에 따라 정적 라우팅과 동적 라우팅으로 크게 두 가지로 분류됩니다 

## 💡 정적 라우팅과 동적 라우팅의 주요 차이점은 무엇인가?

| **구분** | **정적 라우팅** | **동적 라우팅** |
| --- | --- | --- |
| 항목 생성 방식 | 사용자가 수동으로 라우팅 테이블 항목을 채움   | 라우팅 프로토콜 기반으로 자동으로 항목 생성   |
| 유연성 | 유연성이 떨어져 경로 변경 어려움   | 경로상 문제 발생 시 자동으로 경로 우회 가능   |

**목차**

네트워크의 핵심인 **라우팅**의 작동 원리를 깊이 있게 이해하고 싶다면 이 강의가 명확한 해답을 제시합니다. **정적 라우팅**과 **동적 라우팅**의 차이점을 명확히 구분하고, 특히 대규모 네트워크에서 필수적인 동적 라우팅의 핵심인 **라우팅 프로토콜**의 종류와 역할을 상세히 배울 수 있습니다. AS(Autonomous System) 개념을 통해 네트워크의 계층적 구조를 파악하고, RIP, OSPF, BGP와 같은 주요 프로토콜들이 어떻게 최적의 경로를 찾아내는지 구체적인 예시와 함께 설명하여 복잡한 개념을 쉽게 이해하도록 돕습니다. 네트워크 관리자나 개발자 지망생이라면 반드시 알아야 할 실용적인 지식을 얻고, 실제 네트워크 환경에서 발생하는 문제 해결 능력을 향상시키는 데 큰 도움이 될 것입니다.

## 라우팅의 분류와 라우팅 프로토콜

## 1. 라우팅의 분류: 정적 라우팅과 동적 라우팅

## 1.1. 라우팅 테이블 생성 방식에 따른 분류

![](https://resource-release.s3.ap-northeast-2.amazonaws.com/thumbnails/0DXQAjSiRhU/0.jpg)

1. **정적 라우팅 (Static Routing)** 
    1. **정의**: 사용자가 수동으로 라우팅 테이블의 항목을 직접 만들어주는 방식이다.  
    2. **유사 개념**: IP 주소의 정적 할당(수동으로 IP 주소 부여)과 유사하다.  
2. **동적 라우팅 (Dynamic Routing)** 
    1. **정의**: 라우팅 프로토콜을 기반으로 라우팅 테이블 항목을 자동으로 만들어주는 방식이다.  
    2. **유사 개념**: IP 주소의 동적 할당(DHCP 기반 자동 할당)과 유사하다.  

## 1.2. 정적 라우팅의 특징 및 한계

![](https://resource-release.s3.ap-northeast-2.amazonaws.com/thumbnails/0DXQAjSiRhU/54.jpg)

1. **수동 설정 방식**: 사용자가 직접 라우팅 테이블 항목을 채워 넣어 라우팅이 수행된다.  
    1. **운영체제별 명령어**:
        1. **Windows**: "라우트 ADD" 명령어를 사용한다.  
        2. **macOS/Linux**: "라우트 ADD" 명령어를 사용한다.  
        3. **Cisco 라우터**: 라우팅 테이블 항목을 채워 넣는 별도의 명령어가 있다.  
    2. **명령어 예시**: "10.0.0.0 서브넷 마스크 24가 목적지인 패킷을 특정 경로로 전달하라"는 항목을 채워 넣는 방식이다.  
2. **정적 라우팅의 한계**:
    1. **관리의 어려움**: 네트워크 규모가 커지거나, 관리할 라우터 및 라우팅 테이블 항목이 많아질수록 관리가 어렵다.  
    2. **휴먼 에러 발생 가능성**: 수동 작업으로 인해 입력 실수가 발생할 수 있다.  
    3. **유연성 부족**:
        1. 경로상에 문제가 발생했을 때 자동으로 다른 경로로 변경하는 기능이 없다.  
        2. 문제가 발생하면 어떤 라우터에서 문제가 발생했는지 파악 후, 해당 라우터에 직접 접속하여 라우팅 테이블 항목을 수동으로 변경해야 한다.  

## 1.3. 동적 라우팅의 특징 및 이점

![](https://resource-release.s3.ap-northeast-2.amazonaws.com/thumbnails/0DXQAjSiRhU/147.jpg)

1. **자동 라우팅 테이블 생성**: 라우팅 테이블 항목을 자동으로 만들고, 이를 바탕으로 라우팅이 수행된다.  
2. **라우팅 프로토콜 사용**: 라우터들이 경로 정보를 교환하여 최적의 경로를 찾기 위한 프로토콜인 **라우팅 프로토콜**이 사용된다.  
    1. **작동 원리**: 이웃한 라우터들이 서로 경로 정보를 주고받아 각자의 라우팅 테이블이 자동으로 업데이트된다.  
3. **동적 라우팅의 이점**:
    1. **수동 입력 불필요**: 라우팅 항목이 수시로 변해도 직접 손으로 입력할 필요가 없다.  
    2. **경로 자동 갱신**: 경로상에 문제가 발생했을 때, 해당 라우터를 거치지 않고 경로를 우회할 수 있도록 자동으로 경로가 갱신된다.  

## 2. 자율 시스템 (AS: Autonomous System) 개념

![](https://resource-release.s3.ap-northeast-2.amazonaws.com/thumbnails/0DXQAjSiRhU/219.jpg)

1. **정의**: 라우터들의 집단 네트워크를 의미하며, 라우팅 프로토콜의 단위가 되는 라우터 집단이다.  
2. **AS 번호**:
    1. 각 AS에는 고유한 AS 번호가 할당된다.  
    2. 공인 IP 주소처럼 전 세계에서 유일하며, 사설 AS 번호도 존재한다.  
    3. 인터넷에서 AS 번호를 검색하면 어떤 네트워크가 어떤 AS 번호를 할당받았는지 확인할 수 있다.  
3. **라우팅 범위**:
    1. **AS 내부 라우팅**: AS 내부에서 라우팅이 이루어질 수 있다.  
    2. **AS 간 라우팅**: AS 간에도 라우팅이 이루어질 수 있다.  
4. **AS 경계 라우터 (ASBR: Autonomous System Boundary Router)** 
    1. **역할**: AS 외부와 통신할 때 AS 경계에 위치하여 AS 간의 라우팅을 수행하는 특별한 라우터이다.  
    2. **기능**: 사실상 AS 간의 라우팅을 가능하게 하는 경계 라우터이다.  

## 3. 라우팅 프로토콜의 분류: IGP와 EGP

![](https://resource-release.s3.ap-northeast-2.amazonaws.com/thumbnails/0DXQAjSiRhU/343.jpg)

1. **라우팅 프로토콜의 목적**: 라우터끼리 경로 정보를 교환하여 패킷의 최적 이동 경로를 찾기 위한 프로토콜이다.  
2. **AS 기반 분류**: AS를 기준으로 라우팅 프로토콜은 두 가지로 분류된다.  
    1. **IGP (Interior Gateway Protocol)**: AS 내부에서 최적의 경로를 찾기 위한 라우팅 프로토콜이다.  
        1. **대표적인 종류**: RIP (Routing Information Protocol), OSPF (Open Shortest Path First)가 있다.  
    2. **EGP (Exterior Gateway Protocol)**: AS 간의 최적의 경로를 찾기 위한 라우팅 프로토콜이다.  
        1. **대표적인 종류**: BGP (Border Gateway Protocol)가 있다.  

## 4. IGP 라우팅 프로토콜: RIP와 OSPF

## 4.1. RIP (Routing Information Protocol)

![](https://resource-release.s3.ap-northeast-2.amazonaws.com/thumbnails/0DXQAjSiRhU/423.jpg)

1. **특징**: 거리 벡터(Distance Vector)를 기반으로 최적의 경로를 결정하는 라우팅 프로토콜이다.  
    1. **거리(경로)의 의미**: 패킷이 경유한 라우터의 수, 즉 **홉 수(Hop Count)**를 의미한다.  
    2. **최적 경로 판단**: 홉 수가 가장 적은 경로를 최적의 경로로 판단한다.  
    3. **메트릭**: 홉 수가 적을수록 라우팅 테이블 상의 메트릭 값도 작아진다.  
2. **작동 방식**:
    1. RIP 프로토콜을 사용하는 라우터들은 주기적으로 서로 경로 정보를 교환한다.  
    2. 이 과정에서 특정 수신지까지의 홉 수를 계산한다.  
    3. 계산된 홉 수를 기반으로, 패킷이 들어왔을 때 가장 적은 홉 수로 내보낼 수 있는 라우터에게 해당 패킷을 전달한다.  

## 4.2. OSPF (Open Shortest Path First)

![](https://resource-release.s3.ap-northeast-2.amazonaws.com/thumbnails/0DXQAjSiRhU/423.jpg)

1. **특징**: 링크 상태(Link State)를 기반으로 라우팅을 수행하는 라우팅 프로토콜이다.  
    1. **링크 상태의 의미**: 현재 네트워크의 구성(어떤 대역폭을 가진 라우터가 어떻게 연결되어 있는지)을 의미한다.  
    2. **작동 원리**: 네트워크 상태를 그래프 형태로 저장한 뒤, 최단 경로 알고리즘을 수행하여 최적의 경로를 찾는다.  
    3. **약자 의미**: "Open Shortest Path First"는 최단 경로를 우선적으로 찾는다는 의미를 내포한다.  
2. **링크 상태 데이터베이스 (Link State Database)** 
    1. **정의**: 그래프 형태로 표현된 현재 네트워크의 링크 정보를 저장하는 데이터베이스이다.  
    2. **저장 내용**: 라우터들의 연결 관계, 연결 비용 등 네트워크의 상태를 그래프 형태로 저장한다.  
3. **메트릭 계산**: 대부분 **대역폭**을 기반으로 메트릭을 계산하여 최적의 경로를 결정한다.  
    1. **대역폭과 메트릭**: 대역폭이 높은 링크일수록 메트릭이 낮은 경로로 인식되는 경우가 많다.  

## 5. EGP 라우팅 프로토콜: BGP (Border Gateway Protocol)

## 5.1. BGP의 개요 및 종류

![](https://resource-release.s3.ap-northeast-2.amazonaws.com/thumbnails/0DXQAjSiRhU/607.jpg)

1. **정의**: AS 간의 통신에서 주로 사용되는 프로토콜이지만, 엄밀히 말하면 AS 내부 통신에서도 사용 가능하다.  
2. **BGP의 종류**:
    1. **iBGP (Internal BGP)**: AS 내부 통신을 위한 BGP이다.  
    2. **eBGP (External BGP)**: AS 간 통신을 위한 BGP이다.  
3. **개발자 관점**: 개발자 입장에서 BGP를 직접 다루는 일은 많지 않으므로, 배경 지식으로 가볍게 이해하는 것이 좋다.  

## 5.2. eBGP의 피어링 (Peering) 과정

![](https://resource-release.s3.ap-northeast-2.amazonaws.com/thumbnails/0DXQAjSiRhU/666.jpg)

1. **정의**: 다른 AS에 속한 eBGP 지원 라우터와 연결하는 과정을 의미한다.  
    1. **목적**: BGP 연결을 유지하기 위해 BGP 라우터끼리 피어(Peer) 관계를 맺도록 연결되는 과정이다.  
2. **의미**: BGP 기반으로 AS 간 통신이 이루어진다면, 각 AS 내에는 피어 관계를 맺은 BGP 라우터가 하나 이상 존재한다는 것을 의미한다.  

## 5.3. BGP의 최적 경로 결정 과정

![](https://resource-release.s3.ap-northeast-2.amazonaws.com/thumbnails/0DXQAjSiRhU/702.jpg)

1. **복잡성**: RIP나 OSPF에 비해 최적의 경로를 결정하는 과정이 복잡하고 일정하지 않은 경우가 많다.  
2. **고려 요소**: 경로를 결정하는 과정에서 다양한 **속성(Attribute)**과 **정책(Policy)**이 고려되기 때문이다.  
    1. **속성**: 경로에 대한 부가 정보를 의미하며, 다양한 종류가 있다.  
    2. **정책**: AS 관리 주체가 임의로 부여한 의지(선호도)를 의미한다.  
        1. 특정 AS에서 오는 패킷을 우대하거나 차단할 수 있다.  
        2. 보안 안정성을 우선시하거나 성능을 우선시하는 정책을 적용할 수 있다.  
        3. AS 관리 주체에 따라 상이한 정책을 사용할 수 있다.  

## 5.4. BGP의 대표적인 속성

![](https://resource-release.s3.ap-northeast-2.amazonaws.com/thumbnails/0DXQAjSiRhU/771.jpg)

1. **AS 패스 (AS Path)** 
    1. **정의**: 메시지가 수신지에 이르는 과정에서 거치게 되는 AS들의 목록을 의미한다.  
    2. **작동 방식**: 메시지가 한 AS를 거칠 때마다 AS 패스에 해당 AS 번호가 추가된다.  
        1. **예시**: AS 1에서 AS 3을 거쳐 AS 2로 도달하는 경로는 AS 패스에 "3, 2"로 기록된다.  
    3. **경로 벡터 라우팅 프로토콜**: BGP는 메시지가 거치게 될 경로를 고려하므로, **경로 벡터 라우팅 프로토콜**의 일종으로 불린다.  
        1. **거리 벡터(RIP)와의 차이**: 거리는 홉 수(길이)를 의미하지만, 경로는 거친 AS의 목록(어떤 경로를 거쳤는지)을 의미한다.  
2. **넥스트 홉 (Next Hop)** 
    1. **정의**: 다음으로 거칠 라우터의 IP 주소를 의미한다.  
    2. **예시**: AS 1에 속한 라우터가 AS 2에 속한 라우터로 패킷을 보낼 때, AS 2 라우터의 IP 주소가 넥스트 홉 속성으로 명시될 수 있다.  
3. **로컬 프레퍼런스 (Local Preference)** 
    1. **정의**: 지역 선호도를 의미하며, 외부 경로를 선택하는 과정에서 내부적으로 어떤 경로를 가장 선호할지 명시하는 명시적인 메트릭이다.  
    2. **영향력**: 일반적으로 AS 패스나 넥스트 홉 속성보다 메트릭에 큰 영향을 끼치며, 우선시 여겨지는 경우가 많다.  
    3. **정책의 영향**: AS 관리 주체가 설정하는 정책의 영향을 많이 받는 속성이다.  
        1. **정책 예시**: 특정 AS를 우대하거나 차단, 보안/안정성 우선, 성능(지연 시간, 대역폭) 우선 등 다양한 정책이 적용될 수 있다.
