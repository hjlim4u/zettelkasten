인터넷 프로토콜(IP)의 두 가지 핵심 임무: 주소 지정과 데이터 분할

**Introduction: The Internet's Postal Service** [01:20](http://www.youtube.com/watch?v=bI8woqPQFWg&t=80)

인터넷 프로토콜(Internet Protocol, IP)은 디지털 데이터를 위한 전 세계적인 우편 서비스와 같습니다. 우리가 편지나 소포를 보낼 때 주소를 적고, 너무 큰 물건은 여러 상자에 나눠 보내는 것처럼, IP는 인터넷 세상에서 데이터가 정확한 목적지를 찾아가고, 어떤 네트워크를 통과하든 안전하게 전달될 수 있도록 하는 규칙들의 집합입니다. 이 문서는 이 거대한 디지털 우편 시스템을 가능하게 하는 IP의 두 가지 핵심 임무, 즉 데이터의 목적지를 정하는 방법과 큰 데이터를 전송하기 좋게 나누는 방법에 대해 알아봅니다. 이 두 가지 핵심 기능인 \*\*주소 지정(Addressing)\*\*과 \*\*단편화(Fragmentation)\*\*는 인터넷 표준 문서인 RFC 791에 공식적으로 정의되어 있습니다. [01:56](http://www.youtube.com/watch?v=bI8woqPQFWg&t=116)

-----

**1. 첫 번째 임무: 주소 지정 (Addressing) - 모든 데이터에 집 주소 붙여주기** [04:36](http://www.youtube.com/watch?v=bI8woqPQFWg&t=276)

IP의 첫 번째 임무는 네트워크에 연결된 모든 장치(컴퓨터, 스마트폰 등)에 고유한 주소를 부여하는 것입니다. 마치 모든 집이 고유한 우편 주소를 갖는 것과 같습니다. 이 디지털 주소를 우리는 IP 주소라고 부릅니다. 이 주소가 있어야만 데이터를 보내는 송신자와 데이터를 받는 수신자를 정확하게 식별하고 데이터를 전달할 수 있습니다.

가장 널리 사용되는 IP 주소 버전은 IPv4이며, 다음과 같은 구조를 가집니다.

  * **32비트 주소:** 0과 1로 이루어진 32자리 숫자의 조합입니다. [05:24](http://www.youtube.com/watch?v=bI8woqPQFWg&t=324)
  * **4개의 옥텟(Octet):** 사람이 읽기 쉽도록 32비트를 8비트씩 네 부분으로 나눕니다. 각 부분은 0부터 255까지의 숫자로 표현됩니다. [05:50](http://www.youtube.com/watch?v=bI8woqPQFWg&t=350)
  * **점(.)으로 구분:** 이 네 개의 숫자는 점(.)으로 구분하여 표기합니다. (예: 192.168.1.1) [05:36](http://www.youtube.com/watch?v=bI8woqPQFWg&t=336)

IPv4 주소를 집 주소에 비유할 수 있습니다. 주소의 앞부분은 동네( 네트워크 )를 식별하고, 뒷부분은 그 동네 안의 특정 집( 호스트 )을 가리키는 것과 같습니다.

하지만 32비트 체계인 IPv4는 약 43억 개의 주소만 만들 수 있어, [16:19](http://www.youtube.com/watch?v=bI8woqPQFWg&t=979) 인터넷에 연결된 장치가 폭발적으로 증가하면서 주소가 고갈될 위기에 처했습니다. [16:39](http://www.youtube.com/watch?v=bI8woqPQFWg&t=999) 이 문제를 해결하기 위해 IPv6가 등장했습니다. IPv6는 128비트 주소 체계를 사용하여 [17:19](http://www.youtube.com/watch?v=bI8woqPQFWg&t=1039) 거의 무한에 가까운 주소를 제공함으로써 주소 부족 문제를 근본적으로 해결합니다.

  * IPv6 주소 예시: 2001:0db8:85a3:0000:0000:8a2e:0370:7334 [17:33](http://www.youtube.com/watch?v=bI8woqPQFWg&t=1053)

이제 데이터가 어디로 가야 하는지 주소를 알았으니, 다음으로 이 데이터를 어떻게 안전하게 보낼 수 있는지 알아봅시다. 만약 보내려는 데이터가 너무 크다면 어떻게 해야 할까요?

**2. 두 번째 임무: 단편화 (Fragmentation) - 큰 짐을 작게 나눠 보내기** [06:02](http://www.youtube.com/watch?v=bI8woqPQFWg&t=362)

\*\*단편화(Fragmentation)\*\*란 전송하려는 데이터 묶음(패킷)이 특정 네트워크 경로에서 허용하는 크기보다 클 경우, 이를 더 작은 조각으로 나누어 보내는 과정을 말합니다.

거대한 백과사전 전집을 배송한다고 상상해 보세요. 비현실적으로 큰 상자 하나에 모든 책을 담는 대신, 여러 개의 작은 상자에 책을 나눠 담고 각 상자에 번호를 매겨 보내는 것이 훨씬 효율적입니다. IP의 단편화도 이와 같은 원리로 작동합니다.

여기서 중요한 개념이 바로 \*\*MTU (Maximum Transmission Unit)\*\*입니다. [06:27](http://www.youtube.com/watch?v=bI8woqPQFWg&t=387) MTU는 특정 네트워크 경로가 한 번에 전송할 수 있는 "최대 패키지 크기"를 의미하며, 일반적으로 1500바이트입니다. [06:51](http://www.youtube.com/watch?v=bI8woqPQFWg&t=411) 만약 보내려는 데이터 패킷이 이 MTU보다 크면, 반드시 여러 조각으로 단편화되어야 합니다.

이렇게 잘게 쪼개진 패킷 조각들은 목적지에 도착한 후 원래의 온전한 데이터로 다시 합쳐져야 합니다. [07:04](http://www.youtube.com/watch?v=bI8woqPQFWg&t=424) 이 재조립 과정을 정확하게 수행하기 위해, 각 조각에는 특별한 정보들이 기록됩니다. 이 정보들은 IP 헤더의 특정 필드에 담겨 있습니다.

| 헤더 필드 (Header Field) | 역할 (The "So What?") |
| :--- | :--- |
| **식별자 (Identification)** [09:02](http://www.youtube.com/watch?v=bI8woqPQFWg&t=542) | 이 필드는 모든 조각에 동일한 "주문 번호"를 부여합니다. 수신자는 이 번호를 보고 '아, 이 조각들은 모두 같은 데이터에서 온 것이구나\!'라고 알 수 있습니다. |
| **플래그 (Flags)** [10:08](http://www.youtube.com/watch?v=bI8woqPQFWg&t=608) | 패키지에 붙이는 작은 쪽지와 같습니다. 여기에는 두 가지 중요한 정보가 담길 수 있습니다. '이 패킷은 절대 조각내지 마세요 (Don't Fragment)'[10:31](http://www.youtube.com/watch?v=bI8woqPQFWg&t=631)라는 표시와, '아직 조각이 더 남았음 (More Fragments)'[10:42](http://www.youtube.com/watch?v=bI8woqPQFWg&t=642)이라는 표시입니다. 마지막 조각은 '더 남은 조각 없음' (More Fragments = 0)으로 표시되어, 수신자가 '이것이 마지막 조각이구나'라고 인지하게 합니다. [11:05](http://www.youtube.com/watch?v=bI8woqPQFWg&t=665) |
| **단편화 오프셋 (Fragment Offset)** [11:19](http://www.youtube.com/watch?v=bI8woqPQFWg&t=679) | 백과사전의 페이지 번호와 같습니다. 각 조각이 원래 데이터의 어느 부분에 해당하는지 알려주어, [11:53](http://www.youtube.com/watch?v=bI8woqPQFWg&t=713) 조각들이 순서 없이 도착하더라도 수신자가 정확한 순서로 재조립할 수 있게 합니다. |

이처럼 IP는 주소 지정과 단편화라는 똑똑한 방법으로 데이터를 전달합니다. 그렇다면 이 모든 정보는 데이터 패킷의 어디에 기록될까요?

**3. IP 패킷 헤더: 데이터의 "운송장" 살펴보기** [08:08](http://www.youtube.com/watch?v=bI8woqPQFWg&t=488)

IP 헤더는 모든 데이터 패킷의 앞부분에 붙는 "운송장" 또는 "배송 라벨"입니다. 여기에는 데이터가 목적지까지 안전하게 여행하는 데 필요한 모든 핵심 정보가 담겨 있습니다. IPv4 헤더의 주요 정보는 다음과 같이 그 역할에 따라 묶어서 이해할 수 있습니다.

  * **주소 지정을 위한 핵심 정보 (Core information for Addressing):**
      * `Source IP Address` (송신지 IP 주소): 데이터를 보내는 사람의 주소입니다. [15:24](http://www.youtube.com/watch?v=bI8woqPQFWg&t=924)
      * `Destination IP Address` (수신지 IP 주소): 데이터를 받는 사람의 주소입니다.
  * **데이터 단편화 및 재조립을 위한 정보 (Information for Fragmentation & Reassembly):**
      * `Identification`, `Flags`, `Fragment Offset`: 위에서 설명한 것처럼, 분할된 데이터를 재조립하기 위한 정보입니다. [12:54](http://www.youtube.com/watch?v=bI8woqPQFWg&t=774)
  * **안전한 전송을 위한 기타 제어 정보 (Other control information for reliable transport):**
      * `Time To Live` (TTL): 패킷의 "수명"입니다. [13:08](http://www.youtube.com/watch?v=bI8woqPQFWg&t=788) 네트워크 장비(라우터)를 하나 거칠 때마다 1씩 줄어들고, [13:51](http://www.youtube.com/watch?v=bI8woqPQFWg&t=831) 0이 되면 패킷이 무한정 떠도는 것을 막기 위해 폐기됩니다.
      * `Protocol`: 패킷 안에 어떤 종류의 데이터가 들어있는지 알려줍니다. [14:25](http://www.youtube.com/watch?v=bI8woqPQFWg&t=865) (예: TCP는 6번, UDP는 17번) [15:01](http://www.youtube.com/watch?v=bI8woqPQFWg&t=901)

참고로 IPv6 헤더는 IPv4에 비해 구조가 더 간소화되었습니다. [18:04](http://www.youtube.com/watch?v=bI8woqPQFWg&t=1084) 특히 단편화 관련 정보는 기본 헤더가 아닌, 필요할 때만 사용하는 "확장 헤더(Extension Header)"[19:05](http://www.youtube.com/watch?v=bI8woqPQFWg&t=1145)라는 특별한 영역을 통해 처리하여 효율성을 높였습니다. [21:16](http://www.youtube.com/watch?v=bI8woqPQFWg&t=1276) 이는 프로토콜이 시대에 맞게 진화했음을 보여주는 좋은 예입니다.

**4. 결론: 인터넷을 움직이는 보이지 않는 힘** [23:25](http://www.youtube.com/watch?v=bI8woqPQFWg&t=1405)

다시 우편 서비스 비유로 돌아가 봅시다. 인터넷 프로토콜(IP)은 디지털 세상에서 두 가지 필수적인 임무를 완벽하게 수행합니다. 첫째, 데이터가 가야 할 정확한 주소를 제공하고(주소 지정), 둘째, 어떤 경로로든 배송될 수 있도록 큰 짐을 현명하게 나누고 다시 조립하는 방법(단편화)을 제공합니다. 이 두 가지 단순해 보이는 기능이 바로 오늘날 우리가 당연하게 여기는 모든 인터넷 통신을 가능하게 하는 보이지 않는 힘이며, 전 세계의 수많은 네트워크를 하나로 묶어주는 가장 근본적인 약속입니다.
