# 악보 기반 연주 피드백 앱 서비스 개발 자료 조사

악보 파일/PDF/사진과 사용자의 악기 연주 영상/음원을 입력받아 피드백을 제공하려면, 핵심 파이프라인은 다음과 같이 나뉜다.

1. 악보 입력을 기계가 다룰 수 있는 symbolic score로 바꾸기: PDF/이미지 -> OMR -> MusicXML/MEI/MIDI -> 내부 note array.
2. 연주 입력을 분석 가능한 performance representation으로 바꾸기: 영상 -> 오디오 추출, 오디오 -> 피치/온셋/템포/다이내믹/음색 특징 또는 MIDI-like note events.
3. 악보와 연주를 정렬하기: DTW, score following, score-performance alignment로 악보의 각 음표와 연주의 각 이벤트를 연결.
4. 객관 지표로 평가하고 피드백 생성하기: 음정, 리듬, 길이, 템포 안정성, 빠짐/추가음, 다이내믹, 음색, 프레이징 등을 note-level 또는 phrase-level로 평가.

## 기능별 구현 단서

### 악보 파일 및 사진을 MusicXML, MIDI, MEI 등으로 변환

- 우선 포맷은 MusicXML을 중심으로 잡는 것이 현실적이다. W3C MusicXML 4.0은 디지털 악보 교환과 보존을 위한 표준 공개 포맷이며, 발표 당시 250개 이상 앱에서 지원한다고 설명한다.
- MEI는 연구/보존/문헌학적 악보 표현에 강하고, Verovio가 MEI 중심 렌더링과 MusicXML/Humdrum 입력 변환을 지원한다.
- MIDI는 연주 이벤트와 타이밍 분석에는 편하지만, 악보 레이아웃/기보 의미를 보존하기에는 MusicXML/MEI보다 약하다.
- OMR은 Audiveris가 가장 바로 활용 가능한 오픈소스 후보이다. PDF/이미지 악보를 인식하고 MusicXML 4.0으로 내보낼 수 있으며, 100% 자동 인식은 어렵기 때문에 수동 교정 UI를 전제로 해야 한다.
- 딥러닝 OMR은 PrIMuS, Camera-PrIMuS, MUSCIMA++, OMR-Datasets 같은 데이터셋과 Survey 논문을 출발점으로 삼을 수 있다.

### 악기 연주 영상/음원을 그대로 활용하거나 변환

- 영상 입력은 FFmpeg로 오디오 스트림을 추출하거나 표준 포맷으로 트랜스코딩한다.
- 단일 악기 또는 비교적 깨끗한 음원은 Basic Pitch 같은 AMT(audio-to-MIDI) 모델을 써서 MIDI-like note events를 만들 수 있다.
- 음원 전체를 MIDI로 변환하지 않고도 chroma, onset, beat, tempo, pitch contour, loudness, timbre descriptor를 뽑아 score following과 평가에 쓸 수 있다.
- Essentia, madmom, librosa는 오디오 특징 추출과 MIR 태스크 구현 후보이다.
- 영상 피드백까지 확장하려면 손/자세/운지 영상 분석은 별도 컴퓨터비전 문제로 분리하는 것이 좋다. 1차 MVP는 오디오 기반 피드백에 집중하는 편이 현실적이다.

### 악보와 실제 연주 비교 및 피드백

- 비교 기준의 핵심은 score-performance alignment이다. 악보의 note array와 연주의 note/onset/pitch event를 정렬한 뒤, 각 악보 음표에 대해 맞음/틀림/누락/추가/빠름/늦음/짧음/김을 계산한다.
- Partitura는 MusicXML/MEI/MIDI score, MIDI performance, alignment 파일을 다루며 note array를 제공하므로 내부 표현 설계의 좋은 참고 자료다.
- librosa의 DTW 기반 music synchronization 예제는 오디오-오디오 정렬의 기본 구현 단서다. 악보를 합성 오디오나 chroma sequence로 바꾸면 score-audio alignment에도 응용할 수 있다.
- 반복 기호, 도돌이표, 연주자의 생략/반복/점프는 자동 정렬 품질을 크게 떨어뜨린다. "Just Label the Repeats"류 접근처럼 사용자가 반복 점프를 빠르게 주석하는 반자동 워크플로우가 실서비스에 유용하다.
- 평가 지표는 최소한 pitch accuracy, rhythm/onset accuracy, duration, tempo stability를 포함한다. 고급 지표로 intonation cents, dynamics/loudness, articulation, tone quality, phrase-level musicality를 추가할 수 있다.

## MVP 설계 제안

초기 앱은 "피아노 또는 단선율 악기 1개 + MusicXML 악보 + 오디오 업로드" 범위로 제한하는 것이 좋다. PDF/사진 OMR은 Audiveris 연동 후 사용자가 결과를 교정하게 하고, 오디오는 Basic Pitch 또는 pitch/onset extractor로 note events를 만든다. 그런 다음 Partitura/pretty_midi 스타일의 note array로 표준화하고, DTW 또는 note-level alignment를 통해 다음 지표를 산출한다.

- 음정: expected pitch와 performed pitch 차이, intonation cents.
- 리듬: expected onset beat 대비 performed onset deviation.
- 길이: expected duration 대비 performed duration ratio.
- 누락/추가음: alignment에서 unmatched score note와 unmatched performed note.
- 템포: phrase/bar별 local tempo와 tempo drift.
- 다이내믹: MIDI velocity 또는 RMS/loudness contour 비교.
- 톤/음색: spectral centroid, spectral flux, attack stability 등은 고급 피드백으로 후순위.

## 리스크

- OMR은 자동 정확도가 충분하지 않을 수 있으므로 수동 교정과 confidence 표시가 사실상 필수다.
- audio-to-MIDI는 polyphonic, noisy recording, accompaniment가 섞인 입력에서 오류가 커질 수 있다.
- MusicXML은 악보 의미와 레이아웃을 잘 담지만, 실제 연주 표현과는 시간 단위가 다르므로 beat/quarter/second mapping이 필요하다.
- 반복 기호, 코다, 달세뇨, 즉흥, 템포 루바토는 alignment 난도를 크게 올린다.
- 자동 평가는 teacher feedback을 대체하기보다 객관 지표와 근거 구간을 제시하는 보조 피드백으로 설계하는 편이 안전하다.
