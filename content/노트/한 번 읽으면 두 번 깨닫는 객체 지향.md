### (독서) 노트
- 관계의 의존성(결합도)은 낮게, 기능의 집중도(응집도)는 높게 ^f8f448
	- 어떤 모듈이 되도록 하나의 작업만 수행, 작업을 수행하기 위해 다른 모듈에 얼마나 적게 의존
- 객체 지향 소프트웨어의 객체로 구현될 때에는 스스로 판단하고 실행하고 요청하는 주도적인 존재 ^39bcd5
	- 객체가 주도성을 가졌을 때의 장점은 코드 이해가 쉬워지고 가독성이 좋아진다. 객체 간의 관계를 맺는 코드가 줄어들고 객체 역할 이해하기 쉬워진다. ^7205c3
- 절차 지향 언어의 사상과 단점 ^f7b25a
	- 절차 지향 언어는 처리-판단-반복의 기초 문법, 함수 등의 명령어를 활용하여 위에서 아래로(절차적)으로 수행하는 언어
	- '구현하고 싶은 어떤 기능'을 함수로 만들어 로직의 모듈화, 재사용 가능
	- 단점: 함수는 객체지향의 클래스처럼 많은 것을 담을 수 없어 모듈화의 한계 발생, 전역 변수를 여러 함수에서 같이 조작하면 다른 함수에도 사이드 이펙트
- 객체지향 언어를 독립된 단위 객체들의 모임 관점으로 접근
	- 사람이 사물에 대해 인식하는 사고를 거의 그대로 활용하여 
	- 객체는 함수와 달리 기능과 '데이터'도 담고 있어 소유한 데이터를 객체 스스로 관리하도록 유도, 객체 간의 데이터 의존 성 낮아짐, 기능의 집중도 올라감
- 점(객체 하나하나)보다 선(객체 간의 협력(관계))로 접근한다. ^b86abe
	- 객체가 협력에 유연하게 대응하여 문제 해결 용이, 로직 < 인터페이스에 집중
- 객체는 사람이 인식할 수 있는 최소한의 의미를 가진 사물이다. + 객체는 세상에서 유일한 실체가 있는 사물이다.  ^49ada0
- 외연: 일정한 개념에 속하는 모든 객체들의 집합 / 종개념: 하나의 개념 속에 포함되어 잇는 여러 개의 개별 개념
- 범주 : 동일한 성질을 가진 사물을 하나의 단어로 묶은 것
- 분류와 범주 := 클래스 = 추상적 객체화 = 객체 = 구체적
- 객체의 기능을 가장 잘 발휘할 수 잇는 속성/ 다른 객체와 잘 협력할 수 있도록 돕는 속성(점보다는 ) ^2e42bd

- 외연: 일정한 개념에 속하는 모든 객체들의 집합 
- 종개념: 하나의 개념 속에 포함되어 있는 여러 개의 개별 개념
- 분류 : 개념의 외연에 포함된 종개념을 명확히 구분하여 체계적으로 정리
- 범주: 동일한 성질을 가진 사물을 하나의 단어로 묶은 것
- 분류와 범주를 통해 우리는 세상의 사물과 생명의 종류를 추상화 시켜 바라볼 수 있다.(같은 기준으로 묶어 단순하게 표현): 분류와 범주 -> 구체적인 대상 표현(객체화)
- 객체지향 프로그래밍에서는 코드로 만든 설계도인 클래스를 바탕으로, 객체 지향 소프트웨어 세상으로 프로그램을 탄생시키기 위한 작업이 필요하다. 이렇게 클래스를 소프트웨어로 탄생시키는 작업을 객체지향 언어에서는 클래스를 바탕으로 객체를 생성한다고 표현한다. ex ) Airplane airplane1 = new Airplane();
- 새롭게 창조할 객체에 어떤 특징을 부여해야 하는지 고민: 객체가 어떤 속성을 책임져야 하는가?
- 점보다는 선의 관점: 객체가 주어진 역할을 최대한 잘 수행하기 위해서 어떤 기능이 필요할까?
